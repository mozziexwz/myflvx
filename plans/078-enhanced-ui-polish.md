# 078 增强功能界面整改

按整改文档实施，以 HTML 原型核对布局和交互。改动限定在桌面与 H5 导航及四个增强页面，复用现有 API、主题、组件桥接层和拖拽排序组件。

## 任务清单

- [x] 核对两份附件、仓库基线 `67c2b0c9` 与增强功能的现有入口。
- [x] 精简 `admin.tsx` 和 `profile.tsx` 的增强入口，并在 `App.tsx` 保留旧下载路由兼容。
- [x] 收拢 `deploy.tsx` 的协议展示和卡片操作，保留部署任务及其弹窗。
- [x] 在 `proxy-node.tsx` 聚合中转节点，保留筛选和排序，并支持带所选节点直达生成页。
- [x] 在 `subscription.tsx` 合并下载功能，增加卡片和列表切换及折叠导入说明。
- [x] 在 `sub-generator.tsx` 实现 URL 预选、吸顶操作栏、四标签页、折叠代理组与规则列表。
- [x] 运行 TypeScript 类型检查、生产构建，并核对变更范围。
- [x] 在浏览器验收主要流程、亮暗主题及移动端布局。

增强页保留桥接层的下拉容器与触发按钮。菜单项复用桥接层底层的 Radix 组件，以支持真正的禁用态和选择后关闭。

部署卡片把协议标签并排放在同一行，每个标签内上下显示协议名和端口。代理节点拖动源节点时，中转节点跟随源节点显示。同组的中转节点可以单独排序。

## 验证结果

`npx tsc --noEmit`、`npm run build` 和 `git diff --check` 均通过。

Chromium 用模拟 API 验收了旧链接重定向、桌面和 H5 入口权限、部署菜单和确认弹窗、中转聚合与拖拽、三种下载格式、视图切换持久化，以及从批量勾选到订阅生成的完整流程。生成页覆盖了 URL 预选、吸顶栏、代理组折叠、规则列表与源码同步、双处 IPv4 开关和预览告警。

在 1024、1280、1440 和 1536 像素宽的亮色桌面，以及 320 和 390 像素宽的暗色 H5 模式下检查了页面宽度和布局。
