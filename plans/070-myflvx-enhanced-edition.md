# 070 myflvx 增强版（基于 2.2.0-alpha4 UI）

## 目标

- 以 FLVX `2.2.0-alpha4` 的界面为基础，后端与节点端（go-backend / go-gost）同步到上游最新版，吸收之后的 bug 与安全修复。
- 备份恢复与原版兼容：原版（2.2.0-alpha4 ~ 3.x）导出的备份可直接导入；增强版可导出原版能导入的备份。
- 新增「订阅」模块（参考妙妙屋）：节点管理、订阅管理、生成订阅、订阅下载（替代订阅链接，不在公网暴露配置）。
- 节点管理可选择隧道：自动创建转发并生成中转节点。
- 部署节点：参考 mihomo_script，一键部署 Shadowsocks 2022 / mieru / Sudoku 三个协议。

## 设计要点

### 上游修复
- go-backend、go-gost 整体同步到上游 main（3.0.1-rc7 之后）。上游在 alpha4 之后只新增 API，没有删除，alpha4 前端可直接对接。
- 不引入：商业授权（keygen.sh 校验 + 品牌设置付费锁定），保持 alpha4 的免费品牌设置。
- 前端只移植与新 UI 无关的修复（会话/退出、公开配置读取、敏感配置不缓存、弹窗滚动、节点升级、用户禁用提示、离线节点编辑隧道、依赖安全升级）。

### 备份兼容
- 后端 `decodeJSON` 使用 `DisallowUnknownFields`，原版导入时遇到未知字段会整体失败。因此：
  - 主备份结构与上游保持一致，增强版数据作为**可选的新类型**（proxyNodes / subscriptions / proxyDeploys），不勾选时不会出现在文件里。
  - 导出提供格式选择：增强版完整格式 / 兼容原版 3.x / 兼容原版 2.2.0-alpha4（去掉 alpha4 不认识的字段）。

### 订阅模块（管理员）
- `proxy_node`：节点（Clash 代理配置 JSON 为准），来源：手动 / 分享链接或订阅导入 / 部署 / 中转。
- `sub_file` + `sub_file_user`：订阅（上传 YAML / 从 URL 导入 / 生成），可分配给用户。
- 生成订阅：选择节点 + 内置模板（极简 / 常用分流）+ 可视化代理组编辑 + 自定义规则，下载时实时生成。
- 订阅下载：所有用户在面板内（携带登录凭据）下载分配给自己的订阅文件，不提供公网订阅 URL。
- 分享链接解析使用妙妙屋的 MIT 模块 `github.com/MMWOrg/mmwX-plugins/proxyparser`，`sudoku://` 自行解析。

### 隧道中转
- 节点管理中选择隧道 → 以管理员身份走原有转发创建流程（端口分配、下发节点）→ 按转发入口（监听 IP / 节点 IP + 入口端口）生成中转节点，可覆盖连接地址。
- 中转节点在列表与订阅生成时按转发当前入口自动刷新；删除中转节点可同时删除转发。

### 部署节点
- 面板生成全部参数（端口、SS2022 密钥、mieru 用户/密码、Sudoku 密钥），生成 mihomo_script 一键命令。
- 可选 SSH 自动部署（凭据只用于本次，不保存），部署后回读 `/etc/mihomo/share.txt`。
- 部署成功后自动生成 / 更新对应的节点。
